# EXP-035 floodsize — 흐름이 얼마나 작아도 읽나
날짜: 2026-11-06 · 기반: EXP-034 조건 A · 학습: 맥(`launch.sh`, 3가지 × 시드 3개 동시, 스레드 2), 22분 · 스텝: 세대당 공격 2M + 수비 2M + 새 공격 2M, 2세대

## 왜
- EXP-034: 플레이의 30%를 한쪽으로 2.5초 몰아막는 수비로 바꾸자 공격이 1세대에 흐름을 읽었다(좌우 전환 1.00). 읽는 건 LB 위치가 아니라 스냅 뒤 수비가 움직이는 쪽이었다.
- 사용자: "둘 다 진행"(EXP-034 notes 다음 후보 1번 "흐름이 얼마나 작아도 읽나"와 2번 "AI 수비가 속이기를 배우나").

## 미리 잰 것 (학습 없이, EXP-034 A 12세대 공격)
몰아막는 시간만 줄였다(`baseline_EXP-034A_g12_*.log`). "읽기 값" = LB 반대쪽 5야드로 가는 스크립트 러너 - 가장 좋은 고정 방향(AI 블로커).
| 몰아막기 | 읽기 값 (s0 / s1 / s2) | EXP-034 공격 좌우 전환 | 야드 | 읽는 단서(`flood_cue.py`) |
|---|---|---|---|---|
| 2.5초 (EXP-034) | +3.2 / +3.3 / +3.1 | 1.00 / 1.00 / 1.00 | 10.0 | 흐름 |
| 1.0초 | +3.3 / +2.4 / +3.0 | 0.97 / 1.00 / 0.99 | 6.4~7.0 | 흐름 |
| 0.5초 | +5.0 / +5.0 / +4.7 | 0 / 0 / 0 | 5.6~6.0 | 없음 |
| 0.25초 | s0 +3.9 | 0 / 0 / 0 | 8.0~8.3 | 없음 |
| 0.1초 | s0 +1.3 | (안 잼) | | |
| LB 두 명만 2.5초 | -0.1~+0.3 | 0.07 / 0.07 / 0 | 7.1~9.0 | |
- 1.0초까지는 배운 그대로 읽는다(흐름으로). 0.5초부터는 못 본다. 그런데 읽기 값은 0.5초에서 가장 크다(+5야드): 짧게 몰려도 LB 쪽은 막힌다.
- LB 두 명만 몰리면 읽을 값이 없다(DL이 갭을 지켜서). 사다리에서 뺐다.

## 가설
- 몰아막는 시간이 짧으면 흐름이 작아 안 보인다. 그래도 읽기 값이 크면 공격은 다른 단서, 즉 스냅 때 LB 위치를 읽기 시작할 것이다. 그러면 단서가 "흐름"에서 "LB"로 바뀌는 지점이 생긴다.
- 반대로 공격이 움직임만 볼 줄 알면, 0.5초 이하에서는 읽기가 사라진다.
- 자신: 1.0초는 읽는다(거의 확실). 0.5와 0.25초는 반반.

## 시도
- `sim/team_policies.py overload_defense`에 `who`(몰리는 수비: 전부 / LB만)와 `toward`(LB 쪽 / 반대쪽) 추가. `train/selfplay.py --overload-commit`.
- EXP-034 A 그대로(`--overload-share 0.3`)에 몰아막기 시간만: c10 1.0초, c05 0.5초, c025 0.25초. 처음부터 2세대(EXP-034는 1세대에 읽었다).
- `scripts/flood_cue.py`: 같은 공격을 LB 쪽으로 몰아막을 때와 반대쪽으로 몰아막을 때 비교. LB를 읽으면 둘 다 +1, 흐름을 읽으면 반대쪽일 때 -1.

## 판정 기준 (학습 전에 정함)
2세대, 몰아막기 시간마다, 시드 s0 / s1 / s2. 그 시간의 몰아막기 상대로 잰다.
- 읽기 있음: 좌우 전환 평균 0.5 이상, 그리고 시드 2개 이상 0.5 이상.
- 답: 읽기가 있는 가장 짧은 시간(문턱). 그리고 시간마다 단서(흐름 / LB / 섞임, 시드별).
- 사다리라서 합격 / 불합격이 아니다. 예측과 다른 결과도 그대로 적는다.
- 기록: 야드, 1세대와 2세대 좌우 전환, `metrics.csv`의 세대별 몰아막기 야드와 본 공격 야드.
- 재현: `analyze.sh c10 1.0`, `analyze.sh c05 0.5`, `analyze.sh c025 0.25`.

## 결과
**답: 문턱은 0.5초. 단서는 끝까지 흐름이었다.** 0.5초 몰아막기에서 시드 3개 모두 1세대부터 읽었다(좌우 전환 1.00). 0.25초는 시드 1개만 읽었다. LB 위치로 단서를 바꾼 시드는 하나도 없었다. 결과 `c10/`, `c05/`, `c025/`의 `overload_check.log`, `flood_cue.log`.

2세대, 그 시간의 몰아막기 상대, 시드 s0 / s1 / s2.
| 몰아막기 | 좌우 전환 | 읽기 | 야드 | 단서 (몰아막기를 LB 반대쪽으로 뒤집었을 때 전환) |
|---|---|---|---|---|
| 1.0초 | 0.98 / 0.00 / 1.00 (평균 0.66) | 있음 | 9.86 / 8.56 / 9.98 | 섞임(-0.35) / 안 읽음 / 흐름(-0.98) |
| 0.5초 | 1.00 / 1.00 / 1.00 | 있음 | 9.92 / 9.95 / 9.81 | 흐름(-0.99) / 흐름(-1.00) / 흐름(-0.67) |
| 0.25초 | 0.00 / 0.00 / 0.98 (평균 0.33, 진전) | 없음 | 8.74 / 8.97 / 9.74 | 안 읽음 / 안 읽음 / 섞임(-0.21) |

- 1세대도 거의 같다: 1.0초 1.00 / 0 / 1.00, 0.5초 1.00 / 1.00 / 1.00, 0.25초 0 / 0 / 0.99.
- 본 공격 야드(최신 AI 수비 상대, `metrics.csv`, 1 → 2세대): 1.0초 2.4 → 6.1, 7.3 → 6.4, 6.9 → 5.2. 0.5초 6.9 → 8.8, 6.1 → 9.7, 8.0 → 6.4. 0.25초 9.5 → 9.6, 7.2 → 9.7, 8.2 → 7.4. 몰아막기를 섞어도 AI 수비 상대 야드는 크게 떨어지지 않았다.

## 놀라운 점
- **0.5초 흐름도 읽었다.** 2.5초로 배운 EXP-034 공격은 0.5초 몰아막기를 못 읽었다(전환 0). 처음부터 0.5초로 배운 공격은 1세대에 읽었다. 단서가 작아도 그것만 보고 배우면 본다.
- **문턱이 한 방향이 아니다.** 1.0초에서 s1은 읽지 않았다. 대신 늘 가던 쪽(오른쪽)으로 가서 8.56야드를 냈다. 몰린 쪽으로 가도 7.0야드가 나오니 읽을 필요가 작았다. 0.25초는 읽지 않아도 8.7~9.0야드가 나온다. 읽기는 단서가 보이는지만이 아니라, 안 읽는 길이 얼마나 나쁜지에 달렸다.
- **LB 위치는 끝까지 안 썼다.** 0.25초에서 흐름이 거의 없는데도, 공격은 LB 위치를 보는 대신 아예 읽지 않거나 섞어 읽었다(s2: 몰아막기를 뒤집으면 전환 -0.21). 서 있는 자리보다 움직임이 배우기 쉬운 단서다.
- 클립 없음: 이번 차이는 숫자(전환, 단서)로 보인다. 읽는 장면은 EXP-034 클립과 같다.

## 다음 시도

- 남은 질문(사용자 확인 필요): 흐름이 없을 때 LB 위치를 읽게 하려면, 흐름 없이 LB 쪽만 막히는 수비(몰아막기 0초, LB가 그 자리에서 버티기)가 필요하다. EXP-034의 "LB 두 명만" 사전 측정에서는 읽기 값이 0이었다. LB 위치만으로 값이 생기는 수비를 먼저 찾아야 한다.
