# EXP-020 tackle — 태클 확률을 NFL 쪽으로: 막는 사람 없는 수비의 태클 성공 72% → 목표 87%
날짜: 2026-11-04 · 기반: EXP-019 + 태클 확률 조정 · 학습: 클라우드 VM(4 vCPU), 시드 3개 동시 실행, 스레드 1 · 스텝: 실행당 48M

## 왜
EXP-019: 태클 시도 성공 56%, 자유로운 수비(블로커에 안 붙잡힌 수비) 72%, 블록 중 수비 38%, 26% 플레이는 시도 없음. NFL 놓친 태클 약 13%.
사용자: "러너가 태클을 잘 안 당하는 것 같다." → "추천대로 태클 확률부터."
규칙을 바꾸면 어차피 재학습이니 리그 학습보다 규칙을 먼저.

## 무엇을 NFL에 맞추나
- PFF 같은 차팅은 "제대로 기회가 있던 수비가 놓친 것"만 센다. 우리는 팔 닿는 거리에 들어온 모든 순간(0.9초마다)을 시도로 센다.
- 그래서 **자유로운 수비의 시도만** NFL과 비교한다. 목표 87% 성공(놓침 13%).
- 블록 중 수비가 팔을 뻗는 태클은 NFL 차팅에선 대부분 시도로 안 잡힌다. 데이터가 없으니 **지금 값(약 40%)을 그대로 둔다.**

## 시뮬 변경 (옵션: 이전 실험 그대로 재현 가능)
- `--tackle-base 2.3 → 3.2` (모든 태클 로짓 +0.9)
- 새 인자 `--engaged-tackle -1.5 → -2.4` (블록 중 수비는 +0.9를 도로 빼서 그대로)
- 인자는 EXP-019와 실험 이름, 위 두 개, 스레드(3→1, 속도만)만 다름(diff 확인).
- 코드: 시도마다 성공 확률과 블록 여부를 info로 남김(`tackle_p`, `tackle_engaged`, `tackle_by_def`, `tackle_missed_by_def`). 학습 결과에는 영향 없음.
- 리포트(`box_report`, `line_hold`, `read_test`, `side_by_gen`)가 규칙을 하드코딩하던 것을 실행 폴더의 config.yaml에서 읽게 바꿈(`train/run_config.py`). 안 바꿨으면 EXP-020을 옛 규칙으로 평가할 뻔했다. EXP-019는 config.yaml로 다시 만든 설정이 저장된 것과 완전히 같음(테스트).

## 학습 전 측정 (`scripts/tackle_stats.py`, 스크립트 공격 2 × 스크립트 수비 2)
| | EXP-019 규칙 | EXP-020 규칙 |
|---|---|---|
| 자유 수비 성공 | 77~79% | 88~89% |
| 블록 중 수비 성공 | 42~46% | 40~45% |
| 평균 야드 (구멍 읽기 vs 갭 수비) | 5.79 | 5.59 |

AI 러너 상대로는 자유 수비가 72%로 스크립트(78%)보다 낮았다(운동량·옆으로 빠지기를 더 잘 씀). 스크립트 기준으론 +0.7, AI 기준으론 약 +1.0이 필요해서 중간 +0.9.
재학습하면 러너가 다시 피하는 법을 배우니 실제 값은 학습 후에 잰다.
