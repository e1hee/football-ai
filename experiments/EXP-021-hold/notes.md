# EXP-021 hold — 블록은 오래 가게 됐지만(2.5초 54~63 → 73~80%) OL은 여전히 길을 지키지 않는다
날짜: 2026-11-04 · 기반: EXP-020 + 블록 규칙 2개 · 학습: 맥(`launch.sh`, 시드 3개 동시, 스레드 3), 47분 · 스텝: 실행당 48M

## 왜
사용자: "OL 중 몇 명은 앞으로 그냥 돌진해버린다. 끝까지 막거나 경로를 확보해줘야 하는데 안 보인다."
EXP-020 측정(`scripts/ol_jobs.py`, `line_hold`, devlog 2026-11-04):
- 앞으로 나가 아무도 안 막는 OL 시간 8~16%(스크립트 2%). 그중 98~99%는 블록하다 DL이 벗어난 OL, 82~84%는 계속 앞으로 달림.
- 블록은 DL이 벗어나서 끝남(OL이 놓음 0%). 2.5초에 블록 유지 54~63%, 러너는 2.6초에 라인 도달. 벗어난 DL은 1초간 다시 블록 불가.
- AI 러너 + 스크립트 OL이면 s0 0.82 → 1.31야드, s1 0.10 → 1.88야드. 블로킹에 여지가 있다.
가설: 블록이 러너 도착 전에 풀리고, 풀린 OL이 다시 붙을 수 없으니 AI가 "벗겨지면 끝"으로 배웠다. 블록이 오래 가고 다시 붙을 수 있으면 OL이 길을 지키는 쪽으로 배울 것이다. (안 되면 다음은 선수별 정책: devlog 2026-11-04 2번안)

## 시뮬 변경 (옵션: 이전 실험 그대로 재현 가능)
- `--shed-rate 0.25 → 0.15`: DL이 블록을 벗어나는 속도(초당, 같은 체중 기준)
- `--reengage-cooldown 1.0 → 0.3`: 벗어난 DL을 다시 블록할 수 있을 때까지의 시간(초)
- 나머지 인자는 EXP-020과 같음(스모크 실행으로 config diff 확인: 위 두 개, 이름, 스레드만 다름).

## 결과 (12세대) — 원본 [ol_jobs.json](ol_jobs.json), [line_hold.json](line_hold.json), [box_report.json](box_report.json), [tackle_stats.json](tackle_stats.json), [ol_reblock.json](ol_reblock.json)
**가설은 절반만 맞았다.** 블록은 예상(약 70%)보다 오래 갔지만, 늘어난 만큼은 대부분 규칙 효과다. OL이 길을 지키는 쪽으로 배웠다는 증거는 없다.
같은 번호 시드라도 EXP-020과 다른 정책이다(규칙이 달라 처음부터 다시 학습). 시드별 변화보다 평균과 범위를 본다.

### OL이 하는 일 (`ol_jobs`, 같은 시드끼리, 러너가 라인 넘기 전까지. s0/s1/s2)
| | 스크립트 020 → 021 | AI 020 | AI 021 |
|---|---|---|---|
| OL 시간 중 블록 중 | 78 → 84% | 65 / 67 / 71% | 76 / 71 / 77% |
| 아무도 안 막고 1야드+ 앞으로 나감 | 2 → 2% | 16 / 8 / 11% | **7 / 16 / 8%** |
| 그때 근처(1.5야드)에 빈 수비 있음 | 85 → 84% | 8 / 11 / 11% | **13 / 5 / 13%** |
| 러너 라인 도달 전 한 번도 안 막은 OL | 1 → 0% | 9 / 7 / 8% | 2 / 9 / 3% |
| 러너 라인 도달 때 안 막힌 수비(6명 중) | 2.4 → 1.9 | 3.0 / 3.0 / 2.6 | 2.1 / 2.6 / 2.1 |
| 그중 LB | 1.2 → 1.3 | 1.2 / 1.3 / 1.2 | 1.3 / 1.5 / 1.2 |

- 앞으로 나간 OL 평균 12 → 10%. 사실상 그대로이고 s1은 오히려 16%다. 나가 있을 때 옆에 막을 수비가 있는 경우는 5~13%로 스크립트(84%)와 여전히 멀다.
- 안 막힌 수비가 줄어든 건 DL 쪽이다. LB는 그대로 비어 있다(라인 도달 전 LB 블록 56 → 43%, LB 태클 46 → 55%).

### 벗겨진 OL이 다시 붙나 (`scripts/ol_reblock.py`, 이번에 추가)
| | 스크립트 | AI s0 | AI s1 | AI s2 |
|---|---|---|---|---|
| 블록이 끝난 뒤 1초+ 남았을 때 다시 블록 | **95%** | **63%** | **34%** | **55%** |
| 앞으로 나간 OL 중 계속 앞으로 달리는 비율 | 77% | 88% | 92% | 78% |
| 그 OL의 평균 전진 속도 | 0.4 yd/s | 2.2 | 3.9 | 1.6 |
| 앞으로 나간 시간 중 먼저 블록했던 OL 비율 | 100% | 71% | 52% | 74% |

- 스크립트는 옛 규칙에서도 87% 다시 붙었다. 규칙이 허락해도 AI는 3분의 1~3분의 2만 다시 붙는다.
- **비교 한계:** EXP-020 체크포인트는 클라우드 VM에서 학습해 이 맥에 없다. 그래서 EXP-020 AI는 이 리포트로 못 잰다. devlog의 "82~84% 계속 달림, 2.8 yd/s, 98~99%가 블록하던 OL"은 코드가 남아 있지 않아 정의가 같다고 장담 못 한다. 021 안에서 스크립트와 비교한 숫자만 믿는다.

### 라인이 버티나 (`line_hold --mix`, 같은 시드끼리)
| | 스크립트 020 → 021 | AI 020 | AI 021 |
|---|---|---|---|
| 2.5초 블록 유지 | 65 → 80% | 54 / 59 / 63% | **76 / 73 / 80%** |
| DL 백필드(공격 쪽 뒤 공간) 1야드+ 플레이 | 50 → 32% | 98~100% | **84 / 94 / 98%** |
| 2.5초 DL 평균 위치(라인 기준, 음수 = 공격 뒤쪽) | +0.41 (021) | | -0.79 / -1.20 / -1.15 |
| 2.5초 OL 사이 최대 간격 | 2.07야드 (021) | | 3.96 / 3.34 / 3.49야드 |

- 블록 유지는 평균 +18%p, 스크립트는 +15%p. 스크립트와의 차이는 약 7%p → 4%p. 늘어난 양 대부분은 규칙이 준 것이다.
- **블록 유지 ≠ 라인 유지.** 블록이 살아 있어도 DL은 거의 매 플레이 백필드까지 들어온다.

## 놀라운 점
- #story `clips/s1_own_line_vs_script.mp4`: 같은 러너, 같은 수비, 같은 시작. 위(자기 AI 라인)는 OL 한 명이 혼자 앞으로 멀리 달려 나가는 사이 수비 3명이 러너를 뒤에서 잡아 -5.9야드, 아래(스크립트 라인)는 터치다운. 사용자가 말한 "그냥 돌진"이 그대로 보인다. 32플레이 중 터치다운 자기 라인 6, 스크립트 라인 25. (위 과적합 주의와 같이 쓸 것)
- 블록이 오래 가자 **블록에 붙잡힌 수비가 태클 시도의 절반(32 → 51%)** 을 차지했다. 붙잡힌 채 러너에게 팔을 뻗는 시도가 늘어 시도당 성공이 68 → 58%로 떨어졌다. 자유 수비, 블록 중 수비 각각의 성공률은 그대로다.
- #story 후보(클립 없음) s0이 수비 정렬을 읽고 방향을 바꾼다. 자기 수비 상대로 DT(라인 안쪽 수비수)가 왼쪽으로 정렬하면 오른쪽 98%, 오른쪽으로 정렬하면 12%. 수비 제자리 시험에서도 정렬에 따라 오른쪽 0 ↔ 83%. EXP-020에서 s0이 LB를 읽은 것과 다른 신호이고 LB에는 약하게만 반응한다(79 / 66%). 시드 1개뿐이다.
- s1의 스스로 감속 17%: EXP-018~021 같은 시드 경기 중 가장 높다(EXP-017 최고 14%). 그런데 s1은 평균 0.10야드로 가장 못 뛴 시드다. 진짜 "기다리기"인지는 아직 확인 안 함.
