## 움직임 비교: AI는 감속·급회전을 안 한다
사용자 질문: "수비가 속도를 조절하고 급하게 방향 바꾸는 게 안 보인다." → `scripts/movement_compare.py`로 NFL 실제(BDB 2024)와 비교.
- NFL 태클한 DB 마지막 3초: 0.5초 최대 방향전환 중앙값 26°, 60°+ 10%, 최대 감속 중앙값 5.6 yd/s², 속도 낙폭 5.0. 캐치 후 WR도 비슷(28°, 6.1, 5.5).
- AI(셀프플레이 R12 vs T12): 방향전환 13~14°, 60°+ 0~1%, **감속 중앙값 0, 속도 낙폭 0**. 챔피언 러너 vs 각도 태클러는 9°.
- 스크립트 회피 러너는 53~77°까지 꺾음 → 물리 한계 문제가 아님. **AI가 쓸 이유가 없어서 안 쓰는 것.**
- 이유(추정): (1) 반응 지연이 없어 상대가 페이크에 속지 않음. 사람은 0.2~0.3초 늦게 반응하는데 시뮬 선수는 즉시 반응. (2) 태클 공식이 수비의 빠른 돌진에 벌점이 없어서(오히려 운동량이 크면 성공률↑) 브레이크다운할 이유가 없음. (3) 보상이 매 스텝 전진 야드라 감속은 손해. (4) 1v1 오픈 필드에 길을 막는 사람이 없음.
- 덤: 감속 수치 일부(스크립트 20~35 yd/s²)는 실제 감속이 아니라 충돌·태클 순간의 속도 변화. 지표에서 접촉 순간을 빼는 게 맞음.

## EXP-005 반응 지연 + 태클 통제력 (절반의 실패)
- 반응 지연(상대를 0.2초 늦게 봄), 태클 통제력(너무 빨리 들어오거나 러너가 옆으로 비키면 놓침). 기본값 0이라 이전 실험 재현됨.
- 움직임 벤치마크를 접촉 전만 보도록 수정. 이전 "스크립트 러너 53~77°"는 충돌이 섞인 값이었음(정정). 물리 한계는 직접 측정: 5yd/s에서 0.5초에 42°까지 가능, NFL과 비슷.
- 결과: 러너 꺾는 각도는 NFL 수준(17~21° vs 19°). 감속은 양쪽 다 여전히 0. 수비는 브레이크다운 없이 전속력(9.5yd/s)으로 들어가서 65~70% 놓침.
- **수비 학습 붕괴**: 29~36%의 플레이에서 수비가 첫 1초부터 러너 반대 방향으로 달림. "주크에 속는 수비"로 보였던 게 프레임을 찍어 보니 "도망가는 수비".
- 러너 5~7세대는 사이드라인 밖으로 나가는 시기(아웃 51%까지), 8세대에 회복.
- 다음: 수비 학습 신호 보강(접근 보상) 또는 지연 축소/좁은 통로/3v3.

삽질: zsh에서 `$SIM`이 인자로 안 쪼개짐. report 스크립트 문자열 치환이 변수 초기화 줄을 빗나감.

## EXP-006 / EXP-007 — 이상한 수비 고치기
사용자: "수비가 완전 이상해 지금." / "보상 체계가 어떻게 돼 있어? 방향 보고 움직이는 수비도 옵션."
- 키보드 버그: 정책 평균이 [-1,1] 밖으로 나가 SB3가 축별로 잘라서 행동의 96%가 8방향에 몰림. "도망가는 수비" = 모서리에 고정. 행동 범위 ±5로 수정(시뮬이 방향 유지하며 단위원으로 줄임).
- 진단: 수비만 스크립트 러너 상대로 학습시키면 지연·통제력·조기 종료 모두 켜도 정상(94% → 14~29%).
- EXP-006 실패: 수비 먼저 학습 + 미학습 러너(거의 안 움직임) + 느슨한 독주 규칙 → 서 있는 러너를 지나치면 55야드 터치다운 → 수비가 골라인 쪽으로 도망가는 상수 정책을 학습. 100% 도망.
- 고침: 독주 = 앞섬 + 러너가 5yd/s 이상으로 달아나는 중 + 수비보다 느리지 않음. 상대 풀에서 미학습 0세대 제외.
- 진단 중 발견: 고정 러너 상대로 수비가 **사이드라인 밖으로 밀어내기**를 학습(95~98%).
- 사용자 제안 "방향 보고 움직이는 수비" → `read_react_tackler`. 손으로 짠 수비 중 최고(러너 TD 63~66% → 44~47%).
- EXP-007: 교차표가 처음으로 삼각형. 진짜 군비 경쟁. 최신 대 최신 72~78%. 감속은 여전히 0 → 1v1의 한계로 보고 3v3로.

삽질: report 스크립트 nan 표시(태클 시도 0회일 때). zsh 변수 쪼개기는 `${=VAR}`.

## 러너는 왜 감속 안 하나 → EXP-008 몸 방향
사용자: "일대일에서 공격수의 급격한 감속과 방향 전환은 보이지 않아? 필요 없어서 그런가?" → "1대1에 몸방향 먼저 넣어줘"

- NFL `o`(몸 방향) 측정: DB는 움직일 때 26%가 몸과 다른 방향(백페달). 엉덩이 회전 p99 250°/s. 뒤로 최고 속도 0.64배.
- 몸 방향 물리 + 행동 3번째 값 "스퀘어업". `--facing` 없으면 이전과 동일.

- 발견: AI 수비는 페이크(반대로 0.4초 후 꺾기)에 약함, TD 11% → 32%. 손으로 짠 수비엔 안 통함.

삽질: 셀프플레이 상대 풀이 행동 2칸으로 고정돼 있어 3칸 행동이 안 들어감. 출력 grep 버퍼링으로 학습 로그가 끝날 때까지 비어 보임.

사용자: "최소 OL이 몇 명? 그 숫자 + 러너로 맞추면?" / "NFL 팀은 몇 대 몇으로 연습해? 6대6이 너무 크면 3대3에서 더 해도 되고. 인사이트가 필요해" / "1대1에서 조금 더 추가해 보자. 몸 충돌, 통로 드릴 다 넣고 3대3·6대6은 나중에" / "더블팀도 가능해?"
- OL은 사실상 5명(라인 7명 이상 규칙, 50~79번 5명은 고교 규칙에 명시, NFL 원문은 미확인).
- NFL 연습은 인원을 늘려 가는 순서: 1대1 → 하프라인 → 9대7(런) → 7대7(패스) → 11대11. 그래서 통로 드릴(OL + RB 대 DL)부터.
- 내 착오: "선수끼리 통과한다"고 말했는데, 코드를 보니 모든 선수 쌍 충돌이 원래 있었다. 바로 정정.
- 새 규칙: 스냅 때 블록 중으로 시작, 블록당한 DL도 빈 쪽으로 지나가는 러너는 태클 가능, DL 속도 보정.
- 학습 전 스크립트 확인에서 "기다리면 손해"가 먼저 나옴(DL이 블록 중엔 거의 못 움직여서). DL이 옆으로 버티고 힘 70%를 쓰게 하자 늦게 읽는 쪽이 이득.
- 결과: AI 러너가 2세대(4분) 만에 블록을 읽음. 하지만 감속은 0%, 달리면서 읽음. 공격 72% 우세.
- 더블팀: 지금 블록은 1대1 짝만 저장돼서 안 됨. OL 2명 이상인 하프라인 단계에서 넣기로.

삽질: macOS엔 `timeout` 명령이 없음. 렌더러 기본 배율로는 5야드 통로가 점처럼 보여서 통로 전용 확대 레이아웃 추가.

## 2대2 (EXP-014)
사용자: "2대 1인데?" → 맞음, 설명 없이 2대1로 만든 게 내 잘못. LB를 넣어 2대2로.
- 스크립트 수비가 수비 2명일 때 배열 모양 버그 → 학습 전에 발견, 테스트 추가.
- 결과: 수비 압승(9%). AI LB가 러너보다 먼저 구멍에 감.
- 감속 분해: 러너는 스스로 브레이크 0~1%. 2대1에선 라인 전 감속 98%가 자기 OL 등에 부딪힌 것. 충돌이 한 스텝에 속도를 없애는데 대가가 없음 → 균형 규칙 제안.

## 균형 규칙 + 몸 방향 (EXP-015)
사용자: "수비가 이기는 영상 몇 개 더" (태클 유형별 5개 렌더) / "좋아, 그런데 러너가 통과해서 달릴 때 왜 뒤를 쳐다봐?" / "연결했어, 재개"
- 뒤를 보는 이유: 러너가 '가까운 수비 쪽으로 몸 돌리기'를 항상 최대로 씀. 제친 뒤엔 가까운 수비가 뒤에 있음. 2대1에선 대가가 없는 습관.
- 균형 규칙(충돌로 속도가 크게 바뀌면 잠깐 조종 불가) + 러너는 앞의 수비에게만 몸을 돌림. 둘 다 옵션.
- 학습 중 세대당 시간이 85초 → 250초. 원인: 맥북이 8W 충전기, 배터리 6%, 저전력 모드. 프로세스를 일시정지(SIGSTOP) → 사용자가 94W 충전기 연결 → 재개. 저전력 모드는 사용자 설정이라 그대로.
- 결과: 몸 방향 해결, 공격 9→18%, 스스로 감속은 1→3~4%. 결론: 이 드릴엔 기다려서 좋아지는 블록이 없다. 실제 RB의 인내심은 콤보 블록(더블팀 후 LB로 올라가기) 같은 "시간이 걸리는 블록" 때문.

## 콤보 블록 드릴 (EXP-016)
사용자: "학습중?" (아니요, 그때는 멈춰 있었음) / "추천 진행"
- 더블팀(블록 짝을 여러 명으로), 블록 풀기(몸 돌리기 값 < 0.2), 콤보 포메이션. 테스트 4개 추가.
- 스크립트: 더블팀 후 올라가기 32% > 바로 올라가기 25%. 기다리기는 손해(LB가 백필드까지 들어옴).
- 첫 학습: 4세대에 모든 플레이가 시간 초과. 러너가 엔드 라인 앞에서 서성임. 시간 초과를 부트스트랩하는 학습 코드 때문 → 중단, `timeout_ends` 추가, 재학습. 스크립트 러너 뒤로 돌아가는 버그도 같이.
- 결과: AI끼리 48%, 5.4야드(가장 균형). 더블팀은 시드 1개만 배움. 기다림은 여전히 0~1%.
- 생각: 작은 드릴엔 수비가 지킬 다른 책임이 없어 LB가 바로 달려들면 된다. 기다림은 수비가 여러 구멍을 지켜야 할 때 생길 것.

삽질: 다섯 번째 규칙 구멍(시간 초과 부트스트랩). EXP-010 때 "셰이핑은 시간 초과에서 Φ 유지"를 정했으면서, 시간 초과 자체를 진짜 끝으로 볼지는 드릴마다 따져야 했다.
